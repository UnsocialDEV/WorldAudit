WorldAudit

Server-side block, container, lookup, and rollback auditing for Vintage Story.

WorldAudit records what changed in your world, who changed it, what caused it, and gives admins the tools to inspect history, investigate griefing, preview rollbacks, restore changes, and apply fixes safely.

Features

  • Server-side auditing - Runs on the server and stores audit data in SQLite.
  • Block history - Records block placement, breaking, and other block mutations with actor, cause, action, before/after block codes, and timestamps.
  • Container history - Records container transactions with before/after inventory snapshots and per-slot deltas.
  • Inspect mode - Interact with a block or container in-game to see its recent history immediately.
  • Lookup tools - Search audit history around your position with time, radius, user, cause, action, and code filters.
  • Rollback preview jobs - Build rollback plans before applying anything to the world.
  • Restore preview jobs - Rebuild changes from history when you want to put something back.
  • Undo jobs - Generate a new job that inverts a completed rollback or restore.
  • Incremental apply - Applies rollback and restore jobs over future ticks instead of trying to do everything at once.
  • Synthetic re-audit - Rollback and restore changes are logged too, so admin actions remain auditable.
  • Maintenance tools - Includes retention, purge, WAL checkpointing, optimize, queue status, and consumer pause/resume controls.

What Gets Logged

  • Who made the change
  • What action happened
  • The suspected cause when available
  • The time of the change
  • The position of the change
  • The old and new block state
  • Block entity snapshots when relevant
  • Container item movements and slot-level changes

How To Install

  • Install the mod on the server.
  • Start the server once so the config file is generated.
  • Adjust worldaudit.json if you want to change database path, page size, retention, rollback speed, or enable/disable capture systems.
  • Make sure the admins or moderators who need it have permission to use the commands.

Side: Server only

How To Use

1. Inspect a block or container

  • Use /wa inspect to toggle inspect mode on.
  • Then interact with a block or container in the world.
  • WorldAudit will show the recent history for what you clicked, opened, used, or broke.
  • Use /wa inspect again to turn inspect mode off.

2. Search nearby history

  • Use /wa near to search around your current position using the configured default radius.
  • Use /wa lookup when you want more control over filters.

3. Preview a rollback

  • Use /wa rollback with filters to create a preview job.
  • Review the created job before applying it.
  • When you are satisfied, run /wa apply <jobId>.

4. Preview a restore

  • Use /wa restore with filters to create a restore preview job.
  • Apply it later with /wa apply <jobId>.

5. Undo an admin action

  • Use /wa undo <jobId> to create a new preview that reverses a completed rollback or restore job.
  • Apply that new job if needed.

6. Review jobs and system state

  • /wa jobs shows recent rollback and restore jobs.
  • /wa job <jobId> shows one job in detail.
  • /wa status shows queue, rollback, database, and maintenance status.

Command Reference

  • /wa inspect - Toggle inspect mode. Interact with a block or container to view history.
  • /wa lookup [filters] - Search audit history around your current position.
  • /wa near [filters] - Search nearby history using the configured default radius.
  • /wa rollback [filters] - Create a rollback preview job.
  • /wa restore [filters] - Create a restore preview job.
  • /wa undo <jobId> - Create a preview job that reverses a completed job.
  • /wa apply <jobId> - Queue a preview job for execution.
  • /wa jobs - List recent jobs.
  • /wa job <jobId> - Show one job in detail.
  • /wa status - Show runtime, queue, maintenance, and rollback status.
  • /wa reload - Reload the config and rebuild runtime services.
  • /wa consumer pause - Pause database consumption.
  • /wa consumer resume - Resume database consumption.
  • /wa purge t:<age> - Preview a purge by age.
  • /wa purge confirm t:<age> - Execute the purge.

Filter Syntax

These filters can be used with lookup, near, rollback, and restore commands:

  • t:<time> - Time range
  • r:<radius> - Search radius
  • u:<user|#cause> - Player name or cause
  • a:<action> - Block action
  • i:<codes> - Include block codes
  • e:<codes> - Exclude block codes
  • -b - Exclude block history
  • -c - Exclude container history

Example ideas:

  • /wa near t:1d to review recent nearby changes
  • /wa lookup u:PlayerName r:10 to review one player in a specific area
  • /wa rollback t:2h u:PlayerName to preview rolling back a player's recent changes
  • /wa restore t:30m r:5 to preview restoring recent changes in a small area

Configuration Highlights

WorldAudit creates a worldaudit.json config file. Important options include:

  • Database path
  • Writer batch size and flush timing
  • Default page size
  • Default near radius
  • Rollback preview limit
  • Rollback blocks processed per tick
  • Retention days
  • Checkpoint and optimize intervals
  • Enable or disable block audit
  • Enable or disable container audit
  • Enable or disable natural and system cause providers
  • Verbose diagnostics logging

Why Use WorldAudit

  • Investigate griefing and suspicious edits
  • Review container theft and item movement
  • See exactly what changed before touching the world
  • Preview remediation jobs before applying them
  • Restore legitimate builds after mistakes or abuse
  • Keep an auditable record of both player and admin actions
